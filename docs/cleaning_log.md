# 資料處理紀錄

> 用途：作為每項處理決定的書面依據。
> 每一條記錄原始狀態、處理方式、影響筆數、理由。

產生於 `scripts/01_clean.R`。原始資料在 `raw/`，唯讀。

---

## 1. 兩份檔案不可 join

| 項目 | 內容 |
|---|---|
| 原始狀態 | `patient_data.csv` 與 `patient_data_for_survival.csv` 的 `patient_id` 都是 1–100 |
| 檢查方式 | 以 `patient_id` 對齊後比較 `age` 欄位 |
| 結果 | **100 筆中只有 4 筆年齡吻合** |
| 處理方式 | 不合併。兩份資料各自獨立處理 |
| 理由 | 兩份檔案都有 `patient_id` 欄位，但同一個 id 在兩邊指向不同的人。執行 `left_join(by = "patient_id")` 會輸出 100 列、不產生警告，而全部欄位對應錯誤 |

## 2. treatment 編碼統一

| 項目 | 內容 |
|---|---|
| 原始狀態 | survival 檔為 `Drug_A` / `Drug_B`；los 檔為 `A` / `B` |
| 處理方式 | 一律轉成 `Drug_A` / `Drug_B` 的 factor |
| 影響筆數 | los 檔 100 筆 |
| 理由 | 同一變項在不同檔案採用不同寫法，屬真實資料的常見狀況。統一後方可交叉比對 |

## 3. gender 轉中文標籤

| 項目 | 內容 |
|---|---|
| 原始狀態 | `M` / `F` |
| 處理方式 | 轉成 `男` / `女` 的 factor，欄位改名為 `sex` |
| 影響筆數 | 200 筆（兩檔） |
| 理由 | Table 1 的呈現語言為中文。欄位改名以與原始欄位 `gender` 區隔，標示該欄已經處理 |

## 4. stage 轉有序 factor

| 項目 | 內容 |
|---|---|
| 原始狀態 | 字串 `I` / `II` / `III` / `IV` |
| 處理方式 | 轉成 factor，levels 明確指定為 `I < II < III < IV` |
| 影響筆數 | 100 筆 |
| 理由 | 字串預設為字典序。`I, II, III, IV` 恰好正確，但同類編碼（如 `IX`）會排錯。明確指定 levels 為唯一可靠的做法 |

## 5. stage_group：early vs advanced

| 項目 | 內容 |
|---|---|
| 原始狀態 | 四級分期 |
| 處理方式 | `I` / `II` → `early`；`III` / `IV` → `advanced` |
| 影響筆數 | early 49、advanced 51 |
| 理由 | **屬臨床判斷，非統計判斷。** 此處採用最常見的二分法。若 protocol 對 IIB、bulky disease 或 extranodal 另有定義，本條需重寫 |

## 6. age_group：60 歲切點

| 項目 | 內容 |
|---|---|
| 原始狀態 | 連續變項，範圍 31–81 歲 |
| 處理方式 | `>= 60` vs `< 60` |
| 影響筆數 | `<60` 62 人、`>=60` 38 人 |
| 理由 | 供次族群分析使用。**切點為事後決定，該次族群分析因此屬探索性**，不作為結論依據 |
